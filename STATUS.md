# Текущее состояние MyHealth

Актуально на 15 сентября 2026 года.

## Возможности

- Справочник продуктов с названием, брендом, КБЖУ на 100 г и комментарием.
- Получение списка, регистронезависимый поиск, добавление, редактирование и
  удаление продуктов.
- Добавление КБЖУ как на 100 г, так и для произвольного веса с автоматическим
  пересчётом.
- Учёт веса отдельно для каждого пользователя: период, список, добавление,
  замена значения за дату, подтверждаемое удаление и линейный график.
- PostgreSQL-хранилище и автоматические встроенные миграции Goose.
- Локальный PostgreSQL 18.6 Alpine через Docker Compose с постоянным volume.
- Имя пользователя из mTLS-клиентского сертификата; development identity без
  сертификата.
- При запуске через `dev.sh` локальная база временно наполняется данными из
  старой системы.

## Backend

- Go 1.26.5, Gin 1.11, `database/sql`, pgx и Goose.
- Гексагональные слои: entity, port, cases, HTTP/PostgreSQL adapters и service.
- PostgreSQL-адаптер использует фиксированные параметризованные SQL-запросы без
  ORM.
- При запуске сервис подключается к БД, проверяет соединение и применяет
  миграции. При ошибке HTTP-сервер не запускается.
- Конфигурация задаётся только CLI-флагами: `--host`, `--port`,
  `--database-url`, `--require-client-cert`.
- HTTP timeouts и graceful shutdown сохранены.

## Временный импорт legacy-данных

- Исходные выгрузки находятся в `legacy_data`: 165 продуктов и 174 записи
  веса.
- Команда `cmd/legacy-import` применяет актуальные миграции и загружает данные
  до запуска основного backend.
- Старые текстовые ключи продуктов детерминированно преобразуются в UUID v5,
  соответствующие новой модели.
- Записи веса, в которых отсутствовал пользователь, привязываются к локальному
  development-пользователю
  `00000000-0000-4000-8000-000000000000`.
- Используются обычные параметризованные SQL-запросы без ORM. Все наборы данных
  импортируются в одной транзакции через UPSERT, поэтому повторный запуск не
  создаёт дубликаты и не оставляет частично загруженную базу при ошибке.
- Импортер расширяется независимыми загрузчиками: для нового раздела нужен
  отдельный файл в `internal/legacyimport` и регистрация в `datasetLoaders`.
  Команду и `dev.sh` менять не требуется.
- Механизм изолирован от основной архитектуры. После полного перехода можно
  удалить `legacy_data`, `cmd/legacy-import`, `internal/legacyimport` и явно
  помеченные блоки `LEGACY IMPORT` в `dev.sh` и корневом `README.md`.
- Реальный двойной импорт в чистый PostgreSQL проверен: получено 165 продуктов,
  174 записи веса, дубликатов и некорректных UUID нет; тестовые Docker container
  и volume после проверки удалены.

## Frontend

- React 19, TypeScript, Vite, React Router и Recharts.
- Разделы «Еда» и «Вес».
- Каталог, формы, история и график адаптируются к мобильному экрану.
- Старые демонстрационные страницы обзора и измерений удалены.

## API

- Сохранён `GET /api/me`.
- CRUD продуктов расположен под `/api/food`.
- Список, upsert и удаление пользовательского веса расположены под
  `/api/weight`.
- Удалены `/api/health` и `/api/measurements`.
- JSON ограничен 100 КБ; ошибки валидации содержат `details`.

## Deployment

- Release по-прежнему содержит статический Linux backend и собранный frontend.
- Installer принимает именованные параметры, записывает CLI-конфигурацию
  backend в защищённый systemd drop-in и не устанавливает PostgreSQL.
- Database URL хранится в systemd unit-конфигурации и виден в аргументах
  процесса — это принятое ограничение текущей схемы.
- Upgrade сохраняет конфигурационный drop-in; при переходе со старой версии
  необходимо один раз передать `--database-url`.
