# Текущее состояние MyHealth

Актуально на 18 сентября 2026 года.

## Возможности

- Справочник продуктов с названием, брендом, КБЖУ на 100 г и комментарием.
- Получение списка, регистронезависимый поиск, добавление, редактирование и
  удаление продуктов.
- Добавление КБЖУ как на 100 г, так и для произвольного веса с автоматическим
  пересчётом.
- Именованные бандлы из продуктов: поиск, добавление, редактирование, удаление,
  итоговый вес и КБЖУ. В форму можно добавить другой бандл как одну порцию;
  перед сохранением он разворачивается в плоский список продуктов.
- Персональный журнал питания на выбранную дату с шестью приёмами пищи,
  добавлением продуктов и бандлов, очисткой зон, итогами КБЖУ и процентами БЖУ
  по их общей массе.
- Учёт веса отдельно для каждого пользователя: период, список, добавление,
  замена значения за дату, подтверждаемое удаление и линейный график.
- Общий справочник видов спорта с поиском, пагинацией, добавлением,
  редактированием и удалением.
- Персональный журнал спортивной активности: дата, вид спорта и произвольное
  количество подходов. Запись уникальна для пользователя, даты и вида спорта.
- Просмотр активности за выбранный период с вкладками списка и статистики,
  итогами по видам спорта и столбчатым графиком с накоплением подходов.
- Персональные настройки пользователя с дневным лимитом калорий.
- Персональные активные калории за дату с редактированием из журнала и
  fallback на дневной лимит из настроек.
- PostgreSQL-хранилище и автоматические встроенные миграции Goose.
- Локальный PostgreSQL 18.6 Alpine через Docker Compose с постоянным volume.
- Имя пользователя из mTLS-клиентского сертификата; development identity без
  сертификата.
- При запуске через `dev.sh` локальная база временно наполняется данными из
  старой системы.

## Backend

- Go 1.26.5, Gin 1.11, `database/sql`, pgx и Goose.
- Гексагональные слои: entity, port, cases, HTTP/PostgreSQL adapters и service.
- PostgreSQL-адаптер использует фиксированные параметризованные SQL-запросы без
  ORM.
- Состав бандла хранится отдельно от его UUID и имени. Внешние ключи с
  `ON DELETE RESTRICT` запрещают удаление продукта, используемого в бандле или
  журнале.
- Настройки хранятся в `user_settings`: одна строка на GUID пользователя.
  Несохранённая настройка остаётся отсутствующей, дневной лимит ограничен
  целыми значениями от 1 до 10000 ккал.
- Активные калории хранятся в `act_calories` по составному ключу пользователя
  и даты; значение за день имеет приоритет над настройкой по умолчанию.
- Общий справочник спорта хранится в `sport`. Персональные подходы хранятся в
  `sport_activity` по составному ключу пользователя, даты и вида спорта;
  удаление используемого вида спорта ограничено внешним ключом.
- PostgreSQL-массив `sets` при чтении преобразуется в JSON на стороне запроса
  и декодируется в `[]float64`. Это устраняет ошибку `unsupported Scan` драйвера
  при получении спортивной активности.
- Журнал хранит вес продукта на дату и приём пищи отдельно для каждого
  пользователя. Повторное добавление заменяет вес, а внешний ключ запрещает
  удаление используемого продукта.
- При запуске сервис подключается к БД, проверяет соединение и применяет
  миграции. При ошибке HTTP-сервер не запускается.
- Конфигурация задаётся только CLI-флагами: `--host`, `--port`,
  `--database-url`, `--require-client-cert`.
- HTTP timeouts и graceful shutdown сохранены.

## Frontend

- React 19, TypeScript, Vite, React Router и Recharts.
- Разделы «Журнал», «Еда», «Бандлы», «Вес», «Спорт» и «Активность», а также
  страница настроек по клику на плашку пользователя.
- Выбранная дата журнала хранится в URL. Общий асинхронный picker еды и бандлов
  используется формами журнала и бандла.
- Асинхронный группированный поиск еды и бандлов реализован через
  `react-select`; страницы бандлов загружаются отдельными frontend chunks.
- Каталоги еды и бандлов используют серверную пагинацию по 10, 20 или 50
  элементов; фильтр, страница и размер страницы сохраняются в URL. Формы,
  история и график адаптируются к мобильному экрану.
- На странице журнала можно сохранить или удалить активные калории за день;
  прогресс показывает источник лимита и превышение красным цветом.
- Добавление и редактирование спортивной активности выполняется на отдельных
  страницах. Вид спорта выбирается поисковым асинхронным контролом по аналогии
  с выбором еды в журнале; подходы можно добавлять и удалять динамически.
- Страница активности по умолчанию показывает последние шесть месяцев. Во
  вкладке списка записи отсортированы по убыванию даты, внутри даты — по
  возрастанию имени спорта. Вкладка статистики показывает общие итоги и
  накопительный столбчатый график.
- На осях графиков веса и активности даты отображаются как `дд.мм`, а в
  подсказке — полностью. Год подписывается всегда; переходы между годами
  отмечаются вертикальными пунктирными разделителями. Подписи размещены справа
  от разделителя и не выходят за левую ось.
- Категориальная ось графика активности корректно размещает один или два
  столбца внутри области построения. Между выбором активности и графиком
  сохраняется отступ как до, так и после выбора.
- Выпадающий поиск еды в журнале рендерится через portal поверх контейнеров и
  больше не обрезается пустой плашкой приёма пищи.
- Старые демонстрационные страницы обзора и измерений удалены.

## API

- Сохранён `GET /api/me`.
- CRUD продуктов расположен под `/api/food`; список поддерживает `q`, `page` и
  `pageSize` и возвращает метаданные пагинации.
- CRUD бандлов расположен под `/api/bundle`; список использует тот же
  пагинированный контракт.
- Список, upsert и удаление пользовательского веса расположены под
  `/api/weight`.
- Чтение и сохранение настроек текущего пользователя расположены под
  `/api/settings`; ID пользователя берётся только из backend identity.
- Чтение и изменение дневного журнала расположены под `/api/journal`; batch
  добавления бандла выполняется атомарно.
- Получение, upsert и удаление активных калорий за дату расположены под
  `/api/active-calories`.
- CRUD общего справочника спорта расположен под `/api/sport`; список
  поддерживает поиск и стандартную серверную пагинацию.
- Список активности текущего пользователя за период, upsert и удаление записи
  расположены под `/api/sport-activity`. Границы периода включительны.
- Удалены `/api/health` и `/api/measurements`.
- JSON ограничен 100 КБ; ошибки валидации содержат `details`.

## Deployment

- Релиз содержит статический Linux-бинарник Go API, собранный frontend и
  проверяемый SHA-256-манифест; PostgreSQL разворачивается отдельно.
- Установщик настраивает systemd, Nginx с mTLS и проксирование на выбранный
  адрес/порт API. CLI-конфигурация хранится в защищённом systemd drop-in.
- Database URL виден в аргументах процесса — это принятое ограничение текущей
  схемы. При обновлении существующий drop-in сохраняется; если его нет,
  необходимо передать `--database-url`.
- Генератор создаёт клиентские комплекты в каталогах `<uuid>_<имя>`, включая
  варианты для Linux, Windows, iOS/iPadOS и Android.
