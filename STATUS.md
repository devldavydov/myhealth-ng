# Текущее состояние MyHealth

Актуально на 14 сентября 2026 года.

## Назначение

MyHealth — веб-приложение для просмотра и добавления показателей здоровья.
Приложение состоит из Go API, React SPA и набора скриптов для развёртывания
на Ubuntu с обязательной взаимной TLS-аутентификацией.

## Технологии и структура

- Backend: Go 1.26.5 и Gin 1.11.
- Frontend: React 19, TypeScript и Vite 7.
- Точка входа API: `cmd/server/main.go`.
- Конфигурация и жизненный цикл HTTP-сервера: `internal/service`.
- Аутентификация, предметная область, маршруты и репозитории разделены между
  пакетами `internal/auth`, `internal/domain`, `internal/httpapi` и
  `internal/repository`.
- Вся Node.js-инфраструктура, включая `package.json`, `package-lock.json` и
  устанавливаемые зависимости, находится в `client`.
- Скрипты сборки, установки, обновления и удаления находятся в `deployment`.

## Backend

`Service` загружает конфигурацию, создаёт in-memory репозитории, настраивает
Gin-router и `http.Server`, запускает API и выполняет graceful shutdown по
SIGINT или SIGTERM.

HTTP-сервер использует следующие таймауты:

- чтение заголовков — 5 секунд;
- чтение запроса — 10 секунд;
- запись ответа — 15 секунд;
- keep-alive — 60 секунд;
- graceful shutdown — 10 секунд.

Доступны маршруты:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Проверка состояния API |
| `GET` | `/api/me` | Данные текущего пользователя |
| `GET` | `/api/measurements` | Список измерений по убыванию даты |
| `POST` | `/api/measurements` | Добавление измерения |

Поддерживаются типы измерений `weight`, `pressure` и `pulse`. При создании
проверяются тип, конечное числовое значение, единица измерения длиной до
20 символов и дата в формате RFC 3339. Максимальный размер JSON-тела — 100 КБ.

## Пользователи и mTLS

В локальном режиме без сертификата API использует пользователя
«Локальный пользователь» с фиксированным development GUID.

При серверной установке Nginx требует клиентский сертификат для всего
HTTPS-приложения. В API передаются результат проверки и PEM-сертификат.
Backend извлекает:

- имя из `Subject CN`;
- GUID из SAN URI вида `urn:myhealth:user:<uuid>`;
- SHA-256 fingerprint сертификата.

Пользователи запоминаются в памяти процесса по GUID. Скрипт выпуска
сертификатов создаёт новый GUID либо принимает существующий для перевыпуска.
Комплекты формируются для Linux, Windows, iOS/iPadOS и Android и содержат
клиентский сертификат, корневой CA и пароль PKCS#12.

## Хранение данных

Измерения и пользователи хранятся только в памяти процесса. При запуске API
создаются два демонстрационных измерения: вес и пульс. Новые измерения получают
UUID и возвращаются в обратном хронологическом порядке.

Текущее хранилище измерений общее для процесса и не разделяет данные по GUID
пользователя. Переменная `DATABASE_URL` в примере окружения пока не
используется; реализации PostgreSQL нет.

## Frontend

SPA содержит два раздела:

- «Обзор» — демонстрационные карточки состояния, пульса, веса и прогресса;
- «Измерения» — загрузка списка из API и форма добавления веса, давления или
  пульса.

Имя в шапке загружается через `GET /api/me`. Карточки страницы «Обзор» пока
заданы статически и не рассчитываются из сохранённых измерений.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Адрес прослушивания API |
| `PORT` | `3000` | Порт API |
| `CLIENT_ORIGIN` | `http://localhost:5173` | Разрешённый origin для CORS |
| `REQUIRE_CLIENT_CERT` | `false` | Обязательная проверка mTLS-заголовков |

В production-файле `/etc/myhealth/myhealth.env` проверка клиентского
сертификата включена.

## Локальная разработка

Требуются Go 1.26.5 и Node.js 20+.

```bash
npm --prefix client install

go run ./cmd/server
npm --prefix client run dev
```

API доступен на `http://localhost:3000`, frontend — на
`http://localhost:5173`. Vite проксирует запросы `/api` в Go-сервис.

Проверки и сборка:

```bash
go test ./...
go vet ./...
go build -o dist/myhealth-server ./cmd/server

npm --prefix client test
npm --prefix client run build
```

## Сборка и развёртывание

```bash
./deployment/build-bundles.sh <version>
```

Скрипт выполняет тесты и сборку обеих частей приложения, компилирует статический
Linux-бинарник и создаёт `artifacts/myhealth-<version>.tar.gz`. Архив содержит
frontend- и backend-бандлы, deploy-скрипты, номер версии, целевую платформу и
SHA-256-манифест. Архитектуру можно задать через `MYHEALTH_GOARCH`.

На сервере не нужны Go и Node.js. Установщик для Ubuntu настраивает Nginx,
OpenSSL, локальный CA, серверный сертификат и systemd-сервис
`myhealth.service`.

Стандартные пути:

- `/opt/myhealth/releases/<version>` — установленные релизы;
- `/opt/myhealth/current` — активный релиз;
- `/etc/myhealth` — окружение и PKI;
- `/var/lib/myhealth` — рабочий каталог сервиса;
- `/usr/local/lib/myhealth-deployment` — deploy-инструменты.

Обновление проверяет SHA-256 и совместимость архитектуры, устанавливает релиз в
новый каталог и атомарно переключает `current`. Если сервис не запускается,
восстанавливаются предыдущий релиз и предыдущий systemd unit.

Удаление приложения поддерживает опцию `--keep-pki`. Nginx и OpenSSL не
удаляются автоматически.

## Текущие ограничения

- Постоянное хранилище отсутствует; данные теряются при перезапуске и обновлении.
- Измерения не изолированы между пользователями.
- Страница «Обзор» отображает статические демонстрационные значения.
- Нет управления пользователями и сертификатами через API или интерфейс.
- Нет механизма отзыва сертификатов и CRL.
- Нет миграций базы данных, резервного копирования и восстановления данных.
- Серверная установка рассчитана на Ubuntu с systemd и Nginx.
